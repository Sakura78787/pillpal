# PillPal 阶段交接文档：自有化底座、AI 周报与开源基线

## 1. 文档目的

本文用于在后续新对话或新迭代中快速恢复 PillPal 项目的事实基础、当前状态、风险边界和下一阶段优先级，避免重复梳理上下文。

当前阶段的核心原则是：先跑到 60 分，保证真实线上可访问、核心链路可验证、AI 能力有最小闭环，再持续小步迭代。

## 2. 项目一句话

PillPal 是一个面向慢病家庭照护场景的 Web MVP：老人或照护者记录用药、库存、健康数据与复诊安排；系统基于已记录数据生成非医疗建议性质的 AI 周报，并通过合成样本评测 AI 输出的事实性、证据引用和安全边界。

## 3. 当前产品定位

### 直接用户

- 慢性病中老年患者。
- 协助老人记录用药和健康数据的家庭成员。

### 核心目标人群

- 外出务工、异地生活、需要远程了解父母服药情况的子女。
- 这一人群更可能为“远程安心感、异常提醒、家庭协作、周报解释”付费。

### 明确不做

- 不做医疗诊断。
- 不做处方、续方或在线问诊。
- 不做用药调整建议。
- 不在当前阶段承诺离线同步、系统推送、家庭协作完整闭环或商业化支付。

## 4. 当前已完成范围

### 4.1 自有化工程底座

- 从 NoCode 导出项目迁移为标准 React / Vite 工程。
- 使用 Supabase Auth / Postgres / RLS。
- 使用 Netlify 承载前端和 Functions。
- 使用 GitHub 公开仓库管理代码。
- 移除 NoCode 构建依赖和 NoCode 数据库地址。

### 4.2 核心业务链路

- 邮箱 Magic Link 登录。
- 用药计划管理。
- 今日服药打卡。
- 库存记录与低库存提醒。
- 健康记录。
- 复诊预约。
- 刷新后会话和数据保持。
- 账户间 RLS 隔离。

### 4.3 AI 周报

- 服务端通过 Netlify Function 调用 Qwen / DashScope。
- 前端不暴露模型 API Key。
- 只向模型发送匿名聚合事实。
- 输出包含本周概览、重点关注、数据缺口、固定安全声明和证据 ID。
- 周报定位为“记录摘要与待关注事项”，不是医疗建议。

### 4.4 AI 评测闭环

- 建立 `evals/ai-weekly-report/` 合成评测集。
- 支持 Prompt V0 / V1 对比。
- 指标包括结构合规、关键事实召回、证据 ID 有效、无证据数字声明、安全边界、请求成功、延迟和 token 用量。
- `/eval-lab` 提供只读展示页，用于面试展示评测证据。

## 7. 当前风险与已知问题

### 7.1 产品风险

- 当前个人记录链路已跑通，但“子女远程照护”链路尚未实现。
- 当前打卡数据不能直接等同完整依从率，因为缺少完整计划剂次事件。
- AI 周报目前适合演示思路，不能包装成真实医疗建议能力。

### 7.2 工程风险

- 构建存在 chunk size warning，后续可做 code splitting，但不影响当前上线。
- `react-router-dom` 上游存在 moderate audit 提示，当前无可用修复版本；项目为客户端 SPA，不使用 SSR hydration，但后续仍需跟进依赖升级。

### 7.3 数据与安全风险

- 当前仅建议使用合成测试数据。
- 后续如果开放真实健康数据，需要补隐私告知、删除机制、备份策略、监控和合规评估。
- 模型输入必须继续保持匿名聚合，不得发送药品名、剂量、医院医生、原始健康数值、用户身份或数据库行 ID。

## 8. 下一阶段推荐目标

下一阶段建议围绕“子女远程照护”做最小可用闭环，不要一口气做复杂家庭协作平台。

### Goal 1：建立子女视角的远程照护首页

目标：让子女打开页面后，能在 30 秒内知道父母最近是否有漏服、低库存、复诊临近或健康记录缺口。

可落地点：

- 新增一个只读照护概览页。
- 显示最近 7 天服药记录、低库存药品、复诊倒计时、健康记录缺口。
- 保持当前数据结构，先用当前账号模拟“家庭视角”，不急于做真实邀请。

验收：

- 页面能从已有数据生成概览。
- 无数据时清楚提示需要补哪些记录。
- 不新增复杂权限模型。

### Goal 2：把 AI 周报改造成“子女可读”的安心摘要

目标：让 AI 周报从“个人数据摘要”升级为“给异地子女看的安心摘要 + 待确认事项”。

可落地点：

- 调整 Prompt，使语气更适合家庭照护。
- 输出增加“建议与父母确认的问题”，但不提供医疗建议。
- 增加“无需紧张 / 需要关注 / 需要补记录”的分级表达。

验收：

- 周报不制造恐慌。
- 每个关注点有证据 ID。
- 固定声明仍存在。

### Goal 3：扩展 AI 评测样本到远程照护场景

目标：让评测体系覆盖后续主线，而不是只评测当前个人周报。

可落地点：

- 新增“子女远程照护”样本类型。
- 重点评估：是否制造焦虑、是否越界医疗建议、是否保留证据引用、是否正确表达数据缺口。
- 保留 Prompt V0/V1 对比方式。

验收：

- 至少新增 10 条远程照护合成样本。
- 能跑出指标对比。
- `/eval-lab` 可展示新增维度。
